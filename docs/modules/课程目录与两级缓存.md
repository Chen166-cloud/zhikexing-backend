# 课程目录与两级缓存

课程广场提供名称搜索、方向/学历筛选、价格/周期排序、分页和课程详情。详情页可进入 Agent 工作台预填咨询内容，用户点击发送后才创建任务。课程字段直接复用现有 `course` 表；校区为全局目录，不表示某门课程在该校区开设。

## 接口与数据契约

所有浏览接口都经过现有双层登录拦截器。

| 接口 | 返回 |
|---|---|
| `GET /api/v1/courses` | `{items,total,page,pageSize}`，默认第 1 页，每页 12 条，最多 50 条 |
| `GET /api/v1/courses/{id}` | 课程对象；不存在返回 404 |
| `GET /api/v1/campuses` | 全局校区列表，最多 200 条 |

课程查询参数：`keyword`、`type`、`edu`、`sortBy`、`ascending`、`page`、`pageSize`。`edu` 是用户学历等级（0–4），匹配 `course.edu <= edu`；排序字段只允许 `id/price/duration`。名称与输入继续按 MySQL `REGEXP_REPLACE` 去除空白后做 LIKE 查询，排序相同时按 id 升序分页。

课程对象：`id/name/type/edu/price/duration`。id 为字符串；price 为人民币元（整数），duration 为天，可空的展示字段为 null。现有 price 数值不换算，例如 3999 显示为 ¥3,999；它与免费试听订单的 `amountCent` 字段无关。

Agent 内部 `/courses` 仍返回最多 50 条的课程数组，`/campuses` 仍返回最多 100 条。创建试听的目录仍最多 500 个课程选项、200 个校区。三种入口共用 `CourseCatalogService`；内部运行、空间成员校验仍在缓存访问之前执行。

## 缓存范围与流程

仅缓存默认首页（第 1 页、12 条、无筛选、id 升序）、Agent 默认课程列表、创建活动的固定选项、校区列表、按 id 查询的课程详情。不存在的课程用 JSON `null` 缓存。带关键词、筛选、非默认排序或其他分页的查询直接访问 MySQL，不生成海量搜索缓存键。

1. Caffeine `get(key, loader)` 合并同 JVM 同 key 的加载。
2. 本地未命中读取 Redis `catalog:v1:<key>`。
3. Redis 未命中，申请 `catalog:lock:v1:<key>` 的 Redisson `RLock`。
4. 拿锁后再次读取 Redis，仍未命中才查询 MySQL、回填 Redis 和本地缓存。
5. 锁在 finally 释放；不指定固定 lease，使用 Redisson watchdog。等待超时返回 503，不绕过锁回源。

Redis 故障时已有本地数据可在本地 TTL 内继续使用，冷缓存返回 503。锁只减少重复回源，不承担库存扣减、业务幂等或强一致性。登录态、权限、审批、活动状态和试听库存不放入此缓存。

| 环境变量 | 默认值 | 含义 |
|---|---|---|
| `CATALOG_LOCAL_TTL` | `10s` | 本地条目写入后过期 |
| `CATALOG_SHARED_TTL` | `60s` | Redis 条目过期 |
| `CATALOG_MAX_ENTRIES` | `1000` | 每个 Java 实例的本地条目上限 |
| `CATALOG_LOCK_WAIT` | `1s` | 重建锁最长等待时间 |

更新课程数据后，默认展示缓存允许约 60 + 10 秒的延迟（另加查询耗时）；L1 可以在 L2 即将到期时再次缓存旧值。Agent 自身的单 run 30 秒结果缓存还可能叠加延迟。本方案用于低频更新的展示数据，不承诺立即可见。若以后增加课程编辑功能，再增加写后失效。

Redisson 以独立客户端接入，沿用现有 Jedis 的连接地址、认证与数据库配置；不替换 Spring Data Redis 连接工厂。无需新建中间件，也无需新建业务表。

## 观测与验证

现有 `/actuator/prometheus` 可查看：

- Caffeine `cache_gets_total{cache="courseCatalog",result="hit|miss"}` 等命中/淘汰指标。
- `catalog_cache_redis_requests_total{result="hit|miss"}`：L1 未命中后的首次 Redis 查询。
- `catalog_cache_loads_total`：实际触发回源加载的次数，包含失败的加载尝试；一次首页加载会执行 count 和列表两条 SQL。

真实 Redis 测试包含两个独立 Java 子进程，使用共享门闩同时请求冷缓存、验证合计只执行一次 loader；它验证跨 JVM 锁协作，不代表业务吞吐基准。MySQL 集成测试验证真实过滤、分页、单位和字符串 id 契约；MockMvc 验证登录会话和内部运行鉴权仍然生效。

```powershell
$env:CATALOG_TEST_REDIS_PORT = '27379'
$env:CATALOG_TEST_REDIS_DATABASE = '15'
$env:CATALOG_TEST_MYSQL_URL = 'jdbc:mysql://127.0.0.1:28306/zhikexing_catalog_test?allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=UTC'
$env:CATALOG_TEST_MYSQL_PASSWORD = 'catalog-test'
mvn '-Dtest=CatalogAuthorizationTest,CatalogCacheIntegrationTest,CourseCatalogIntegrationTest' test
```

这些变量应指向隔离测试服务；测试使用随机记录与 Redis 命名空间，不清空数据库。CI 在现有隔离中间件中另建课程测试数据库。
