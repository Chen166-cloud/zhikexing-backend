# 登录保护

登录与注册共用 `AuthLoginGuard`，会话由 `AuthSessionService` 管理。复用现有 Redis 和 Java `Semaphore`，没有引入新的安全框架。BCrypt 强度仍为 12。

更新日期：2026-09-29。本文描述当前源码与已更新的完整 Compose。Java、隔离 Redis 和前端 mock API 验证通过；重建后经 8088 真实 API 验证新注册加 3 次登录生成第 4 个会话后，最早 Token 返回 401，其余 3 个仍有效，退出后 Token 返回 401。连续 5 次密码错误触发 429 冷却，冷却期间正确密码仍返回 429 和 `Retry-After: 60`。真实浏览器完成注册、退出、重新登录并进入课程广场。浏览器内会话淘汰、任务续跑和生产容量仍未联调；本轮 API 实测不替代隔离并发测试，详细范围见[部署验证记录](../deployment/Docker部署验证记录.md)。

## 请求流程

```text
格式校验 → 获取本机并发槽 → Redis 全局限流 → 查询用户
        → 按数据库用户 ID 检查账号限流、冷却 → BCrypt 校验
        → 成功清理失败计数 → 原子创建会话并淘汰超额会话
```

注册也获取同一个并发槽并检查全局限流，再查询用户名、执行 BCrypt 哈希和创建会话。旧密码升级同样在并发槽内。并发满时立即拒绝，使用 try-with-resources 释放槽位，不排队等待。

## 默认参数

| 环境变量 | 默认值 | 作用 |
|---|---:|---|
| `AUTH_GLOBAL_ATTEMPTS` | 20 | 登录与注册共用的窗口内请求上限 |
| `AUTH_GLOBAL_WINDOW_SECONDS` | 1 | 全局固定窗口，秒 |
| `AUTH_ACCOUNT_ATTEMPTS` | 10 | 每账号窗口内的密码校验请求上限 |
| `AUTH_ACCOUNT_WINDOW_SECONDS` | 60 | 账号固定窗口，秒 |
| `AUTH_MAX_CONCURRENT` | 4 | 每个 Java 实例同时处理的认证请求数 |
| `AUTH_FAILURE_THRESHOLD` | 5 | 触发冷却的密码失败次数 |
| `AUTH_FAILURE_WINDOW_SECONDS` | 600 | 从首次失败起计数的固定窗口，秒 |
| `AUTH_COOLDOWN_SECONDS` | 60 | 达到失败阈值后的冷却时长，秒 |
| `AUTH_MAX_SESSIONS` | 3 | 每账号最多保留的会话数 |

参数配置在 `application.yaml` 的 `app.auth` 下，Compose 从 `.env` 传入；均应设为正整数。Redis Lua 原子检查和计数，多个后端实例共享频率与冷却；并发上限是每实例的本机限制。

账号额度使用查询到的 `user.id`，MySQL 接受的大小写、重音等用户名变体不会绕过账号保护。未知用户和密码错误统一返回“用户名或密码错误”，未知用户不会进行 BCrypt 校验，也不创建账号计数键。

第 5 次密码失败返回 429 并进入冷却，同时删除本轮失败累计。冷却期间拒绝请求不延长冷却，期满重新计数；成功登录清除失败计数。成功登录不会重置频率额度，避免用有效密码绕过频率限制。

| 情况 | HTTP 状态 | 响应 |
|---|---:|---|
| 频率超限、失败冷却 | 429 | `Retry-After` 为剩余秒数 |
| 本机并发满、Redis/数据库不可用 | 503 | `Retry-After: 1` |
| 用户名或密码错误 | 200 | 保留原业务协议，`ok: 0` |

429/503 同样保留 `ok,msg,data` 响应结构，现有前端能够显示 `msg`。Redis 限流检查失败时停止认证，不继续进行 BCrypt。

Vue 登录/注册页读取 `Retry-After` 并显示倒计时，等待期间暂停提交，到期恢复按钮；Java CORS 配置暴露该响应头，跨域访问也可以读取。前端倒计时仅改善交互，实际限流仍由后端执行。

## 会话数量

登录和注册都创建 32 位随机 Token，空闲超过 24 小时过期。每账号的 ZSET 按创建顺序记录会话；新增会话前清理过期成员，超过上限时删除最早创建会话的 Token。续期不会改变创建排名。

创建、读取续期、退出和昵称更新通过 Lua 原子执行。续期和昵称更新只操作仍存在且在索引中的会话，已退出或淘汰的 Token 不会被重新创建。退出同时删除 Token 和索引成员。

会话使用新的 `login:v2:token:` / `login:v2:sessions:` 命名空间，升级后旧 `login:token:` 会话失效，用户需重新登录；旧键沿原 TTL 自然过期。脚本按本项目的单机 Redis 编写，不支持 Redis Cluster。

浏览器收到 401 会清 Token 并返回登录页。Agent Runtime 和 Java 内部工具使用独立 `AGENT_INTERNAL_TOKEN` 与持久化任务身份，不依赖浏览器 Token；会话被淘汰不会取消已经提交的后台任务，Python 项目无需修改。

## 验证

普通流程与 HTTP 响应测试不依赖外部服务。真实限流与会话测试连接专用测试 Redis，不调用模型，也不清空整个数据库。以下命令在 Java 仓库根目录执行，Docker 引擎需已启动，27379 端口需空闲：

```powershell
docker run --rm -d --name zhikexing-auth-test-redis -p 127.0.0.1:27379:6379 redis:8.2.1-alpine
$env:AUTH_TEST_REDIS_PORT = '27379'
$env:AUTH_TEST_REDIS_DATABASE = '15'
mvn -q '-Dtest=AuthFlowTest,AuthLoginGuardIntegrationTest,AuthSessionIntegrationTest' test
```

使用 WSL 内的独立 Docker Engine 时，先按[部署文档](../deployment/Docker部署文档.md)启动引擎，将上面的 `docker` 换成 `wsl --user root --exec docker`；Maven 仍在 Windows 执行。测试完成后停止专用容器并清除测试环境变量：

```powershell
docker stop zhikexing-auth-test-redis
Remove-Item Env:\AUTH_TEST_REDIS_PORT, Env:\AUTH_TEST_REDIS_DATABASE
```

覆盖多实例共享限流、并发计数、冷却恢复且拒绝不续期、成功清计数、BCrypt 前拒绝、异常释放并发槽、并发登录会话上限，以及退出/淘汰后续期和昵称更新不能复活 Token。

2026-09-29：`AuthFlowTest` 10 项 MockMvc/Mockito 测试、`AuthLoginGuardIntegrationTest` 6 项与 `AuthSessionIntegrationTest` 6 项隔离 Redis 8.2.1 测试全部通过，共 22 项；`mvn -q clean package` 通过，后续 CORS 调整编译通过。CI 将流程测试加入构建回归，真实 Redis 测试复用现有试听测试环境的独立 DB 15。

Vue 类型检查与生产构建通过；Playwright mock API 覆盖登录 429、注册 503 的倒计时与恢复、等待期间重复提交拦截、普通密码错误后修正、登录成功及 401 清 Token 返回登录页。Agent 的 14 项 fixture/模拟 Java 工具回归通过。

同日完整 Compose 已重建。真实 8088 API 验证三会话上限、最早会话淘汰、退出失效及 60 秒失败冷却；浏览器完成注册、退出和重新登录。并发与竞态边界仍以隔离测试为依据，部署结果见[部署验证记录](../deployment/Docker部署验证记录.md)。

这是应用层 demo 保护：固定窗口边界允许突发流量；账号短冷却仍可能被恶意触发；统一错误文案没有消除未知账号的响应耗时差异。当前不包含 IP 限流、验证码、入口请求体限制或网络层 DDoS 防护，默认额度也不是生产容量结论。

## 权威资料与取舍

- [OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)：登录节流、失败计数、统一错误文案，以及账号锁定被滥用的风险；采用短冷却自动恢复。
- [OWASP DoS](https://cheatsheetseries.owasp.org/cheatsheets/Denial_of_Service_Cheat_Sheet.html)：廉价检查先于昂贵操作，限制资源消耗；在 BCrypt 前拒绝超额请求。
- [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 与 [Spring Security Password Storage](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)：密码哈希刻意消耗资源；保留强度，并限制执行并发。
- [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)：并发会话策略由应用选择，淘汰需要在服务端使会话失效。
- [NIST SP 800-63B-4 §3.2.2](https://pages.nist.gov/800-63-4/sp800-63b.html#rate-limiting-throttling)：失败尝试节流和成功后的计数重置；此实现不声明完整 NIST 合规。
- [Redis INCR](https://redis.io/docs/latest/commands/incr/) 与 [Lua](https://redis.io/docs/latest/develop/programmability/eval-intro/)：将检查、计数及设置过期合为一个原子操作。
- [Java Semaphore.tryAcquire](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/concurrent/Semaphore.html#tryAcquire())：无等待地限制同时执行的请求。
- [MySQL 字符串比较](https://dev.mysql.com/doc/refman/8.0/en/case-sensitivity.html)：数据库比较可能忽略大小写；账号限制采用数据库主键。
- [MDN Retry-After](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Retry-After)：429/503 响应告知客户端再次请求前的等待时间，页面按本后端返回的秒数倒计时。
