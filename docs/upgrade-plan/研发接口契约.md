# 本次研发接口契约

用于 Java、Python、Vue 并行开发。新接口返回直接 JSON 对象，错误为 `{code,message}`；已有登录接口继续使用 `{ok,msg,data}`。浏览器只访问 Java，沿用 `Authorization` 登录 Token。所有 ID 使用字符串，JSON 字段采用 camelCase。

项目位置：Java 后端 `D:/java/SpringAI/intelligent-integrated-interaction-platform`；Vue 前端 `D:/develop/web-intelligent-integrated-interaction-platform`；独立 Python 项目 `D:/develop/intelligent-agent-runtime`（包名 `iiip_agent`）。通过 HTTP 联动，Docker 使用独立构建上下文。

## 对外 API：Java `/api/v1`

- `GET /workspaces` → `[{id,name,role}]`，为登录用户建立个人工作空间；`POST /workspaces {name}` 创建空间。
- `GET /conversations?workspaceId=...` → `[{id,title,workspaceId,createdAt}]`。
- `POST /conversations {workspaceId,title}` → 同上对象；`GET /conversations/{id}?workspaceId=...` → `{...conversation,messages:[{id,role,content,runId,createdAt,citations}]}`。
- `POST /runs {workspaceId,conversationId,clientRequestId,input,knowledgeBaseIds?,mode?}` → `{runId,conversationId,status}`。mode 为 `agent` 或 `chat`；同一 clientRequestId 同内容返回原运行，不同内容返回 409。
- `GET /runs?workspaceId=...` → 运行数组；`GET /runs/{id}?workspaceId=...` → `{runId,conversationId,workspaceId,status,input,answer,error,usage,steps,citations,createdAt,updatedAt}`。
- `GET /runs/{id}/events?workspaceId=...&after=0` → SSE；每条 `id: seq`、`event: type`、`data: {runId,seq,type,data,createdAt}`。支持 Last-Event-ID；历史事件先重放，终态后关闭。
- `POST /runs/{id}/cancel {workspaceId}`；`POST /runs/{id}/retry {workspaceId}`；`POST /runs/{id}/inputs {workspaceId,input,clientRequestId}`。
- `GET /approvals?workspaceId=...&runId=...` → `[{id,runId,actionId,status,version,args,expiresAt,result}]`；`POST /approvals/{id}/decision {workspaceId,decision,expectedVersion}`，decision 为 `APPROVED` / `REJECTED`。
- `GET /knowledge-bases?workspaceId=...` → `[{id,name,workspaceId}]`；`POST /knowledge-bases {workspaceId,name}`。
- `GET /documents?workspaceId=...&knowledgeBaseId=...` → `[{id,title,status,version,chunkCount,error,createdAt}]`；`POST /documents` multipart：workspaceId、knowledgeBaseId、file；`DELETE /documents/{id}?workspaceId=...`；`POST /documents/{id}/retry {workspaceId}`。
- `GET /documents/{id}/content?workspaceId=...` 返回授权原文件；`GET /documents/{id}/chunks?workspaceId=...` → `[{id,page,content}]`。
- `GET /evaluations?workspaceId=...` → 评测批次数组；`POST /evaluations {workspaceId,knowledgeBaseId,cases:[{question,expectedText?,expectedDocumentId?}]}` → 评测批次；`GET /evaluations/{id}?workspaceId=...` → 批次及逐例结果。
- `GET /metrics?workspaceId=...` → `{runCount,successRate,totalTokens,estimatedCostCny,averageLatencyMs,statusCounts}`。

运行状态：QUEUED、RUNNING、WAITING_INPUT、WAITING_APPROVAL、SUCCEEDED、FAILED、CANCELLED、TIMED_OUT。事件至少包括 run.started、step.started、tool.started、tool.completed、message.delta、message.reset、message.completed、input.required、approval.required、usage.updated、run.completed、run.failed、run.cancelled。中间事件 data 为展示用简短说明，不保存隐藏思维链。引用修正时 `message.reset` 只清除该 run 的流式回答草稿，保留用户输入和工具轨迹；最终以持久化的 message.completed 为准。

Java 已接受、Python 尚未建立运行时，GET 单个 run 返回 QUEUED、`execution:null` 及 `submission` 投递信息。客户端短轮询等待 execution 建立，再订阅 SSE；DELIVERED 仅表示投递完成，不能当作模型执行成功。

## Java → Python

内部路径 `/internal/v1`，使用 `X-Internal-Token`，并由 Java 注入 `X-Actor-Id`、`X-Workspace-Id`，不转发客户端伪造的同名头。除 workspaces、approvals 外，路径与外部 API 对应。

Java 负责空间成员校验。内部调用需每次携带可信 actor/workspace，Python 在持久化对象查询中再次限制 workspace。创建 run 时由 Java 提供 runId、actorId、workspaceId 及原始字段，Java 用业务事务和 outbox 保存投递，Python 按 runId 幂等接收。

## Python → Java 业务工具

内部路径 `/internal/v1/tools`，同样使用内部 Token 与 actor/workspace 头；运行工具额外携带 `X-Run-Id`。Java 独立复核成员和 run 归属。

- `POST /courses {type?,edu?,keyword?,sortBy?,ascending?}` → 有界课程数组，沿用 Course 的 id/name/type/edu/price/duration。
- `GET /campuses` → 校区 id/name/city 数组。
- `POST /draft-reservation {actionId,courseId,schoolId,studentName,contactInfo,remark?}` → `{id,runId,actionId,status,version,args,expiresAt}`，args 包含查回的课程/校区显示名。
- `GET /approvals/{id}` → 审批对象。
- `POST /execute-reservation {actionId,approvalId}` → `{reservationId,actionId,status,...}`，相同 actionId 只创建一笔预约；参数取已批准草稿，不接收模型新参数。
- `GET /reservations/by-action/{actionId}` → 已提交结果或 404。

Python 在 WAITING_APPROVAL 状态轮询/持久化恢复检查审批，避免仅靠一次通知。审批不占用模型请求。取消先在 Java 持久化写操作禁止标记，执行预约事务锁定同一运行记录。

课程关键词和数据库课程名去除空白后匹配，返回值保留原始名称；查询参数仍以绑定参数传递。图 v3 在单个 run 内缓存 30 秒的成功只读查询结果，tool.completed 的 cached 标记说明是否复用；再次命中同一空结果时转 WAITING_INPUT，避免反复访问工具。知识证据缓存复用前重新校验可见性，审批和写入不走缓存。

## 已接受命令与版本约束

Java outbox 和 RabbitMQ consumer 在创建运行时设置可信内部头 `X-Command-Delivery: true`。Java 代理不会转发浏览器伪造的该头。已向用户接受的命令如在投递时遇到会话占用，Python 持久化 `FAILED / CONVERSATION_BUSY` 和终态事件，再确认消息；普通内部创建仍返回 409。失败输入在重试获准后才进入模型上下文，避免污染原活动任务。

每个运行及 checkpoint 固定图版本、提示词/工具 Schema 哈希、提供方、聊天模型与 Embedding 配置。不兼容部署不会继续执行旧审批；恢复原版本后可重试。费用预算在发出下一次模型请求前检查，默认 `AGENT_COST_LIMIT_CNY=0.10`；单次请求可能越过阈值，未知 usage 不作零费用处理。

## 配置与测试边界

默认模型百炼 qwen3.7-flash，Embedding text-embedding-v4 / 1024；共用 DASHSCOPE_API_KEY，迁移期允许读取已有 API-KEY。内部 Token 配置为 AGENT_INTERNAL_TOKEN；Python 地址为 AGENT_RUNTIME_URL，默认本地 8000。默认真实模型；明确启用 fixture profile 才能使用模拟响应。SQLite 只用于本地隔离验证，正式部署采用 PostgreSQL/pgvector；业务采用 MySQL。
