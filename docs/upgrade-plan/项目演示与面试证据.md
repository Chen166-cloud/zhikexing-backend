# 项目演示与面试证据

核对日期：2026-09-26。知课行演示使用合成课程与用户；业务验证范围以[试听模块验证记录](../modules/免费试听秒杀验证记录.md)和[开发与验证记录](开发与验证记录.md)为准。`zhikexing` 全栈 Compose 健康，真实浏览器完成注册、登录、产品首页、工作台与试听页面导航；隔离真实 Redis/RocketMQ 的 15+3 项测试和完整 Compose 的 Agent fixture 跨服务烟测通过。真实百炼模型、真实 API 的 MEMBER 浏览器权限和浏览器内 Agent 审批尚未验收。不要将隔离负载写成生产数据。

## 演示顺序

1. 打开 `http://localhost:8088/login`，展示知课行登录、`/register` 注册、登录后的 `/` 产品首页和 `/agent` 工作台入口；说明首页功能卡提供导航与概览，实际业务数据在工作台查看。
2. 展示三仓库架构：Vue 工作台，Java 持有身份、审批和业务账，Python LangGraph 持有运行状态；MySQL、PostgreSQL/pgvector、Redis 和 RocketMQ 各有明确职责。
3. 以合成 PDF/课程演示知识查询、证据引用和普通预约草稿，说明 Java 固定审批参数，模型不能直接写业务表。
4. OWNER 在 `/agent`“免费试听”标签从课程与校区目录创建限量活动，发布、暂停并查看只读对账；成员浏览详情并直接抢课。
5. 展示本人持久参与记录和按 `requestId` 回查：HTTP 202、`PENDING/RESERVED` 都不是订单成功；刷新或换设备后仍可恢复本人最近 100 条记录。
6. 让 Agent 查询活动并生成 `claim_trial` 草稿。批准后展示同一 `actionId` 的参与请求，说明审批 `EXECUTED` 仅表示提交。只有 `SUCCEEDED + orderId` 证明已获免费试听资格。
7. 展示隔离真实中间件测试的事务消息、重复消费和库存守恒结果；解释事务回查、MySQL 条件库存、唯一键和失败补偿分别解决什么，不把单机正确性测试写成生产吞吐。
8. 展示 MySQL 业务表的雪花 ID 与逻辑外键约束：新写入主键由应用生成，跨表引用在服务层校验，唯一键与事务继续保护业务不变量。

## 简历措辞

**AI Agent 研发：** 设计独立 FastAPI/LangGraph Runtime，支持检索证据、人工审批暂停与恢复；将免费试听抢课建模为查询活动、固定参数草稿、批准后以稳定 `actionId` 提交、跨运行回查订单终态的工具链。Java 持有身份和业务真相，Agent 不凭自然语言宣布订单成功。

**Java 后端开发：** 在 Java 21/Spring Boot 4.1.1 服务中实现 MySQL 持久请求、Redis Lua 原子预占、RocketMQ 事务消息和异步 0 元订单；通过库存条件更新、唯一约束、事务回查、恢复器与对账处理重复投递及不确定状态。同一 Broker 承载 Agent 普通命令，Java 消费者通过内部 HTTP 将命令交给 Python 幂等接收。新写入 MySQL 业务主键采用应用生成的雪花 ID，关联字段为逻辑外键并在服务层校验。

可引用的验证：MySQL 8.4.8 上 Flyway V1–V7 新库迁移通过，16 张应用业务表为 0 自增列、0 物理外键；前端构建与浏览器注册、登录、首页、工作台和试听页面导航通过。隔离真实 Redis/RocketMQ 的 15+3 项测试以及完整 Compose 的 Agent fixture 跨服务烟测通过，后者确认直接抢课和 Agent 审批均落成零元订单并保持库存守恒。真实百炼模型、真实 API 的 MEMBER 浏览器权限、浏览器内 Agent 审批、QPS、p95、真实用户规模及线上效果没有对应证据。

## 面试追问与证据

| 问题 | 关键回答 | 证据 |
|---|---|---|
| 为什么 Agent 不直接执行抢课？ | 模型只能查询和起草；用户批准固定活动参数，Java 再按可信 actor/workspace/run 执行 | [产品契约](../product/产品功能说明书-研发版.md)、[模块设计](../modules/免费试听秒杀与Agent联动.md) |
| 事务消息为何还需要幂等？ | 半消息与本地事务缩小不确定窗口，消费者仍可能重复；请求、库存条件更新和订单唯一键决定最终结果 | [模块设计](../modules/免费试听秒杀与Agent联动.md)、[验证记录](../modules/免费试听秒杀验证记录.md) |
| 为什么预占成功不等于抢到？ | Redis 只是准入层；消费者 MySQL 事务提交并返回 `SUCCEEDED + orderId` 才是订单事实 | [接口契约](研发接口契约.md)、[模块状态](../modules/免费试听秒杀与Agent联动.md) |
| Redis 丢失活动库存怎么办？ | 停止受理，保留持久请求与订单，对账和人工裁决；不能按数据库剩余量覆盖预占键 | [恢复边界](../modules/免费试听秒杀与Agent联动.md) |
| checkpoint 已保存为何仍需 actionId？ | Java 业务已提交而图尚未保存下一节点时会重放，原 actionId 查回同一业务结果 | [接口契约](研发接口契约.md) |
| 为什么取消物理外键后仍要校验关联？ | 服务端写入前核对空间、用户、课程、校区等关联；数据库仍保留唯一键、非空和库存条件更新，避免把“无物理 FK”理解为无约束 | [Java 业务实现](Java业务改造与验证记录.md) |
| 雪花 ID 的验收边界是什么？ | 业务主键由应用生成，节点编号避免冲突；验证结构中无自增列，并在实际业务写入中检查 ID、引用与幂等键 | [部署与结构验证](开发与验证记录.md) |

面试展示每个数字时，连同测试环境、模型类型和日期一起说明；完整 Compose 的 fixture 联调和真实浏览器 OWNER 抢课路径可作为工程证据，真实百炼模型效果、真实 API 的 MEMBER 权限及浏览器 Agent 审批还不算已验收结果。
