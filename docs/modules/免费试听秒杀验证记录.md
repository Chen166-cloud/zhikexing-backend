## 合成数据与断言

- 合成课程“Agent研发试听”、校区“线上”，均使用隔离库中的10001编号；不存在真实学生姓名、手机号。
- 40个参与主体争抢8个名额，16个线程执行准入；8个成功预占各投递3次，最终8单、32拒绝、数据库和缓存剩余均0。
- 同key同内容回原回执，换活动409；其他成员不能查询他人请求；同活动同用户新key拒绝。
- Lua成功但持久请求仍PENDING时，重放不二次扣库存；缺全部缓存或缺单独receipt时保持UNKNOWN。
- 已RESERVED后缓存丢失仍依据数据库COMMIT，消费成单；再次publish不会补满LIVE活动缓存。
- 人工制造数据库库存0，消费拒绝并进入补偿；重复补偿不重复加库存；补偿凭证丢失继续保留待办。
- Redis时间校验未开始/已结束；活动暂停阻止新准入，已预占请求仍能完成；只允许OWNER对账。
- Direct/Agent共享用户限流，幂等回执重放不被作为新参与限流；篡改审批参数hash不匹配拒绝。
- 未批准不能执行；普通预约不能使用抢课审批；重复执行返回原申请；新的合法run能查此前action；先取消run阻止新报名。
- 真实RocketMQ发送HALF后触发本地回调，消费者最终落单。普通命令HTTP503后重投的path、body、actor/workspace、内部token和delivery标记一致。

没有在这次回归中用网络代理实际截断COMMIT数据包，也没有做Broker主从切换；“二阶段丢包→Broker主动回查”目前依据实现协议与回查单测，不写成已完成故障注入。

## 复现核心回归

需要JDK21、Maven、Docker Compose。使用`deploy/trial-test/compose.yml`，项目名`iiip-trial-test`；端口23306/26379/19876/10911/10909，与主部署数据端口区分。测试库固定`iiip_trial_test`，固定密码只用于这个隔离环境，绝不复制到正式部署。

Windows使用WSL引擎时先按部署文档保持WSL会话存活，在以下Docker命令前加 `wsl -d <你的发行版> --exec` 并使用仓库的Linux绝对路径。一个前台WSL终端可避免systemd服务因发行版空闲退出；本次首次连接失败即由该环境问题引起，保持会话后回归通过。

```sh
docker compose -f deploy/trial-test/compose.yml up -d --wait
docker compose -f deploy/trial-test/compose.yml exec -T broker sh mqadmin updateTopic -n nameserver:9876 -b 127.0.0.1:10911 -t iiip_trial_claims -a +message.type=TRANSACTION
docker compose -f deploy/trial-test/compose.yml exec -T broker sh mqadmin updateTopic -n nameserver:9876 -b 127.0.0.1:10911 -t iiip-agent-bridge-test -a +message.type=NORMAL
```

PowerShell（仓库根目录）：

```powershell
$env:TRIAL_TEST_MYSQL_URL='jdbc:mysql://127.0.0.1:23306/iiip_trial_test?allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=UTC'
$env:TRIAL_TEST_ROCKETMQ='true'
mvn -q '-Dtest=TrialProtocolTest,TrialIntegrationTest,RocketMqBridgeIntegrationTest' test
```

报告在`target/surefire-reports`。不设测试环境变量时，实库/实MQ用例会明确跳过，不能把这种运行当集成通过。不要执行未筛选的原`IiipApplicationTests`，其中有真实模型调用。CI新增独立中间件job，但本地通过不代表尚未触发的远程CI已经通过。

## 复现HTTP + Agent演练

先执行核心回归以创建隔离演示课程/校区。创建额外NORMAL主题`iiip-agent-e2e-commands`（同上updateTopic命令），避免遗留失败命令阻塞本次演练。

启动两个独立前台进程。Java设置测试DB/Redis，`ROCKETMQ_ENABLED=true`、`ROCKETMQ_NAME_SERVER=127.0.0.1:19876`、`AGENT_RUNTIME_URL=http://127.0.0.1:28000`、`AGENT_INTERNAL_TOKEN=isolated-trial-http-token`、`SERVER_PORT=28080`、`MANAGEMENT_PORT=28081`，旧AI关闭；启动参数增加：

```text
--spring.ai.model.chat=none --spring.ai.model.embedding=none
--rocketmq.agent.topic=iiip-agent-e2e-commands
--rocketmq.agent.consumer-group=iiip-agent-e2e-consumer
```

Python设置 `AI_PROVIDER=fixture`、同一个测试internal token、`JAVA_TOOL_BASE_URL=http://127.0.0.1:28080`、`PORT=28000`，`STORAGE_ROOT` 指向新建测试目录，`AGENT_DATABASE_URL=sqlite+aiosqlite:///测试目录绝对路径/agent.db`。将模型Key、S3 endpoint与观测凭据留空，执行其虚拟环境的 `python -m iiip_agent`。

Java启动确认完成后执行：

```powershell
./deploy/trial-test/Verify-Http.ps1
```

脚本只允许127.0.0.1:28080，自动注册随机合成用户、选择本人OWNER空间、创建两场2名额活动，验证直接申请重放与Agent批准后的成单。它不输出登录token。反复运行创建不同合成用户和活动。

演练结束先停止这两个测试进程，再执行 `docker compose -f deploy/trial-test/compose.yml down --volumes` 清理**隔离测试项目**。该命令不得改为主部署Compose路径。合成Runtime目录和JUnit报告可留作本地证据，不提交数据库文件。
