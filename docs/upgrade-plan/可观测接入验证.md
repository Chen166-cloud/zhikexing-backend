# 可观测接入与验证

核对日期：2026-09-26。Python 使用以下 OTel/Langfuse 接入；试听模块在 Java 暴露 `trial_transaction_total`、`trial_consume_total`、`trial_send_total` 指标。`zhikexing` 完整 Compose 的应用与观测服务已启动健康；具体指标抓取值、Langfuse 轨迹和 Grafana 看板的端到端展示应在当前环境单独核对，不沿用其他部署的累计计数。

## 接入模块

Python 独立工程的 `zhikexing_agent/observability.py` 提供三个接口：

```python
from .observability import configure_telemetry, generation_span, record_generation_usage

# 启动时创建一次；返回实例专用 tracer 和同步关闭函数。
tracer, shutdown_telemetry = configure_telemetry("zhikexing-agent-runtime")

# 在异步模型调用外使用普通 with，OpenTelemetry 上下文支持协程传递。
with generation_span(
    tracer,
    run_id=run.id,
    workspace_id=run.workspace_id,
    conversation_id=run.conversation_id,
    provider=settings.provider,
    model=settings.chat_model,
) as span:
    message, usage = await model_provider.chat(messages, tools, emit)
    record_generation_usage(span, usage)

# 先等待业务任务关闭，再在退出生命周期中调用一次。
await asyncio.to_thread(shutdown_telemetry)
```

模块不改全局 TracerProvider，不会影响其他库已配置的遥测。没有导出目标时返回 noop tracer，不创建发送线程。这里的 `messages` 只传给模型，遥测 helper 不接收或保存正文。

## 环境配置与字段

| 配置 | 行为 |
|---|---|
| `OTEL_EXPORTER_OTLP_ENDPOINT` | Collector HTTP 根地址，自动追加 `/v1/traces` |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | 可选完整追踪地址，优先于根地址 |
| `LANGFUSE_BASE_URL` | Langfuse 实例根地址 |
| `LANGFUSE_PUBLIC_KEY`、`LANGFUSE_SECRET_KEY` | 项目密钥，只用于请求认证，不写入 span 或日志 |

两个目标同时配置时使用两个独立批量处理器，各自接收相同 span。只配置 Langfuse 根地址而没有任何项目密钥时，该目标保持关闭；提供不完整的密钥配置会明确报错。每个 HTTP 导出请求超时为 5 秒。

Langfuse 使用 `/api/public/otel/v1/traces`、Basic 认证及 `x-langfuse-ingestion-version: 4`；模型 span 设置 generation 类型及模型、用量字段。依据：[Langfuse 官方 OpenTelemetry 文档](https://langfuse.com/integrations/native/opentelemetry)、[OpenTelemetry Python 导出器文档](https://opentelemetry.io/docs/languages/python/exporters/)。

每次模型调用保留 run/workspace/conversation 编号、provider、model、输入/输出 Token 与总 Token。未知用量保持缺失。异常只保存类别，不自动采集异常正文或堆栈；模型输入、回答和检索文本均不进入 span。

`estimatedCostCny` 写入 `langfuse.observation.metadata.estimated_cost_cny`，同时标记 `cost_currency=CNY`。Langfuse 原生成本字段采用 USD，因此本模块不会把人民币数字写成美元，也没有凭空换汇。[Langfuse 字段映射](https://langfuse.com/integrations/native/opentelemetry)

## 验证边界

当前源码中可核对 OTel helper 的 noop、双导出器、地址与认证映射、Token/CNY 字段、异常隐私及未知用量处理；已验证 Java 业务指标通过 Actuator 导出并被 Prometheus 抓取。完整 Compose 服务健康和业务烟测通过不证明 Collector/Langfuse 已接收试听业务轨迹或 Grafana 图表可见。Langfuse 页面、Grafana 看板、Java HTTP 上下文传播及 Python 工具调用子 span 仍需分别验证，不能声称已经完成分布式全链路追踪。
