## 9 分半演示顺序

演示环境使用独立演示库和合成材料。提前准备一份两页中文 PDF、一个 READY 知识库、一个可展示的已完成运行，以及课程/校区演示数据。先查看 Python `/health` 确认实际 provider 与模型；图版本从运行详情的 `usage.configuration.graphVersion` 读取。本项目演示使用百炼，fixture 仅作为测试证据。登录、模型密钥和内部凭据不放入录屏。

| 时间 | 实际操作 | 讲清楚什么 / 展示什么证据 |
|---|---|---|
| 0:00–0:40 | 打开工作台，展示工作空间和三服务架构图 | Vue 展示过程，Java 决定业务权限与事务，Python 负责可恢复任务；同一百炼 Key 调用 Qwen 与 Embedding |
| 0:40–2:05 | 上传合成 PDF，查看异步状态、片段和原文预览；等待较久时使用提前准备的 READY 文档 | 原文件进入 MinIO，文档、版本和片段独立保存；完整新版本发布后才参与检索。现场状态与已完成样例明确区分 |
| 2:05–3:20 | 选择知识库提问：“请依据文档说明演示课程的上课地点，并引用依据。”打开返回的证据及原文页码 | 工具事实、流式回答、证据编号和页码可复核。刷新后展示历史，说明 SSE 有序号和游标重放；不展示隐藏思维链 |
| 3:20–5:05 | 新会话输入：“请查找 Python与AI应用演示课程，选择上海演示校区，为演示同学准备预约，联系 demo@example.invalid，提交前让我确认。” | 查看课程、校区真实查询结果和审批卡；名称空白差异已归一化。缺信息时按页面补充，不靠操作者修改数据库凑结果 |
| 5:05–6:10 | 在 WAITING_APPROVAL 时按部署文档单独重启 Python，刷新后再批准 | 暂停来自持久化 checkpoint；批准触发 Java 事务，随后展示实际预约编号。用该 run/action 的只读查询核对一条动作记录对应一笔预约 |
| 6:10–7:15 | 展示另一份已验证的取消或重复消息案例及数据库结果；如现场演示取消，使用新任务 | 取消完成后 Java 禁止新业务写入；重复投递允许发生，重复提交同一 actionId 返回原结果。避免为演示直接重放未知生产消息 |
| 7:15–8:15 | 展示规则评测的逐例结果及未评分样本；按 runId 展示模型观测 | 答案、证据、Token、费用和延迟有记录；无参考断言不算通过。Langfuse 的模型观测不保存提示词和回答正文，也不代表跨服务追踪已完整覆盖 |
| 8:15–9:30 | 展示 ADR、一次真实失败修复、备份恢复结果和待完成项 | 可选讲 MySQL 旧快照导致幂等响应失败，或 h2c 使 POST body 丢失；解释如何执行验证、读取反馈并修正。结束于项目能证明什么、尚未证明什么 |

现场模型响应具有波动，不承诺固定完成秒数。超出演示时段时，保留当前运行状态，切换到注明日期和 runId 的真实记录讲解；不要将预存答案描述为本次实时输出。演示入口与重启方法见 [Docker 部署文档](../deployment/Docker部署文档.md)。

## 两条可直接使用的简历表述

**AI Agent 方向：** 设计并实现课程咨询与知识问答 Agent，采用独立 FastAPI/LangGraph 服务、百炼 Qwen 与 text-embedding-v4，完成文档版本管理、pgvector 与中文词项 RRF 混合检索、证据引用校验、人工审批 interrupt 和 checkpoint 恢复；通过真实模型、PostgreSQL 与浏览器验证 RAG、审批重启恢复及 SSE 重放，接入模型用量与费用观测。

**Java 后端方向：** 将项目升级至 Java 21、Spring Boot 4.1.1 与 Spring AI 2.0.1，实现空间权限、BCrypt 渐进升级、Flyway 数据迁移和异步任务 API；采用事务 outbox、RabbitMQ 持久投递与确认、租约重试、审批 CAS 及 actionId 幂等事务，验证重复消息不重复执行业务、取消后禁止新写入，并完成独立数据卷备份恢复演练。

面试时将测试次数解释为工程回归规模，不解释为用户规模、业务准确率或吞吐量。未做正式压测，不填写 QPS、p95 性能承诺；目前的小样本规则评测不能写成“准确率达到某百分比”。

## 附录：八项架构决策记录

以下是当前选择及重新评估条件；撤销条件是后续决策依据，不表示已经实现备选方案。

| ADR | 决策 | 代价 | 撤销或调整条件 |
|---|---|---|---|
| 01 双语言 | Java 保留身份、审批和业务事务；独立 Python 承担模型适配、LangGraph 与知识任务，通过明确接口协作 | 两套依赖、镜像、调试与接口兼容管理，跨服务故障必须可见 | 团队维护成本持续高于能力收益，且单语言路线通过同一恢复/审批/检索验收时，合并运行时 |
| 02 双数据库 | MySQL 保存业务与 outbox；PostgreSQL 保存运行、消息、checkpoint 和 pgvector；服务不跨库写对方表 | 无跨库原子提交，需要异步交接、幂等与两套备份恢复 | 业务资产可迁移且统一数据库能降低运维成本时，先验证数据迁移，再统一存储 |
| 03 单编排器 | LangGraph 负责任务执行状态；Java 负责审批与预约业务状态，前端只显示事实 | 运行状态与业务状态需对账，不能把消息投递和业务成功混为一谈 | 若引入外部工作流，先明确谁拥有执行状态并迁移；不能同时保留两个竞争的任务编排器 |
| 04 重复投递与幂等 | 事务内写 task_request/outbox；事务外投递，confirm 后标记发送完成；消费者先落库；runId/request hash 和 actionId 约束重复处理 | 可能重复消息，有重试、租约、死信与交接空档；不宣称跨系统 exactly-once | 若简化为同进程事务边界，可减少消息层；只要仍跨网络提交业务，就保留幂等约束 |
| 05 checkpoint 与副作用 | checkpoint 恢复计算进度；Java 以已批准参数和稳定 actionId 控制外部提交，恢复后查真实结果 | 要维护业务动作记录，checkpoint 与提交之间仍存在可重放时间窗 | 新工具若无幂等键、状态查询或补偿能力，先限制为人工处理，不能直接复用自动提交路径 |
| 06 RRF 检索 | 同空间、知识库和活跃版本过滤后，融合向量排名与中文词项排名；默认不启用本地重排 | 词法扫描与简单排名存在规模/质量限制；重排收益尚未测得 | 冻结数据集显示另一链路在质量、延迟和成本上更合适时，选择 BM25、重排或简化为 dense |
| 07 历史窗口 | 完整消息独立保存；新任务初始化使用最近窗口，不把窗口存储当永久历史；本 run 工具状态随 checkpoint 保存 | 远期约束可能遗忘；字符截断不是 Token 精算，当前缺少完整摘要和长期偏好治理 | 长对话实测出现约束丢失时，加入可追溯摘要和类型化事实，同时保留原消息 |
| 08 单 worker，暂不多 Agent | 一个 worker 并发处理多个任务；同会话限制活动任务，PG advisory lock 阻止误开竞争 worker；默认单 Agent | 扩容和可用性有限；advisory lock 不等于分布式 fencing，多 Agent 收益尚未证明 | 实测容量需要扩容后补分布式领取/fencing；多 Agent 只有在冻结数据集对照有净收益时启用，两者分别验收 |

按本次开发要求，新增临时测试类和脚本在验证后清理，保留生产评测入口、去敏报告和可复核的数据关联；自动审批拒绝导致的残留目录已在[清理结果](开发与验证记录.md#临时验证文件清理结果)单独登记。该做法不应被包装为完整长期自动回归体系；后续恢复常驻自动化回归需作为新的工程工作明确安排。
