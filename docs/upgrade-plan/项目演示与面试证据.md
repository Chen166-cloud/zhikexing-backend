## 演示顺序

1. 打开 `http://localhost:8088/login`，展示注册、登录后的产品首页及课程广场、Agent 工作台入口。
2. 进入 `/courses`，搜索 Python、筛选方向/学历并查看详情，说明价格单位为元、学习周期为天；点击咨询进入 `/agent`，展示课程名与 ID 已预填、用户发送前没有创建任务。
3. 展示三仓库架构：Vue 提供页面，Java 持有身份、审批和业务账，Python LangGraph 持有运行状态。结合课程页说明 Caffeine 本地缓存、Redis 共享缓存和 Redisson 重建锁的职责；展示 400 RPS 三档对照的 HTTP P95、目录 SQL 与共享缓存查找计数，以及双实例冷键 20 轮均只回源一次的结果。
4. 以已保存的合成资料与运行记录展示知识引用、普通预约草稿和实际回执，说明 Java 固定审批参数。fixture 用于流程复现；真实模型任务与 RAG 评测使用 2026-10-01 报告，区分规则通过率、业务写入对账和检索指标。
5. OWNER 在 `/agent`“免费试听”标签选择课程与校区，创建、发布、暂停限量活动并查看对账；直接抢课后展示本人参与记录和 `requestId`。只有 `SUCCEEDED + orderId` 表示已获名额。
6. 运行 `deploy/Verify-Compose.ps1` 或展示其记录，核对 fixture Agent 的 `claim_trial` 草稿、审批、请求终态与库存账；说明审批 `EXECUTED` 仅表示提交，浏览器内审批操作尚未验收。
7. 展示隔离真实 Redis/RocketMQ 测试的事务消息、重复消费和库存守恒结果，解释事务回查、条件库存更新、唯一键与失败补偿分别解决什么。
8. 展示 MySQL 业务表的雪花 ID 与逻辑外键约束：新写入主键由应用生成，跨表引用在服务层校验，唯一键与事务继续保护业务不变量。
9. 展示登录保护：BCrypt 前检查请求频率和冷却，并发满立即拒绝。真实 8088 API 已验证第 4 个会话淘汰最早 Token、退出失效和第 5 次密码错误触发 60 秒冷却；前端倒计时可结合 mock 浏览器记录说明。

## 简历措辞

**AI Agent 研发：** 设计独立 FastAPI/LangGraph Runtime，支持检索证据、人工审批暂停与恢复；将免费试听抢课建模为查询活动、固定参数草稿、批准后以稳定 `actionId` 提交、跨运行回查订单终态的工具链。Java 持有身份和业务真相，Agent 不凭自然语言宣布订单成功。

**Java 后端开发：** 在 Java 21/Spring Boot 4.1.1 服务中实现 MySQL 持久请求、Redis Lua 原子预占、RocketMQ 事务消息和异步 0 元订单；通过库存条件更新、唯一约束、事务回查、恢复器与对账处理重复投递及不确定状态。同一 Broker 承载 Agent 普通命令，Java 消费者通过内部 HTTP 将命令交给 Python 幂等接收。新写入 MySQL 业务主键采用应用生成的雪花 ID，关联字段为逻辑外键并在服务层校验。

**登录资源控制：** 使用 Redis Lua 在 BCrypt 校验前限制全局与账号请求频率、记录失败冷却，结合 `Semaphore` 控制认证并发；通过 ZSET 与原子会话操作限制每账号登录数量，避免已淘汰 Token 被续期恢复。完成 10 项流程测试和 12 项真实 Redis 回归，前端按 `Retry-After` 显示重试倒计时。

**课程目录与两级缓存：** 实现课程广场的搜索、筛选、排序、分页和详情咨询联动；为低频更新的默认目录与详情接入 Caffeine + Redis 两级缓存，使用 Redisson 分布式锁和锁内二次检查协调多实例缓存重建。2026-10-01 本机 400 RPS、每档 3×180 秒热读对照中，相对 MySQL 直查，HTTP P95 三轮中位数由 3.935 ms 降至 2.446 ms（降低 37.84%），目录 SQL 调用减少 99.9917%；双实例 100/300 并发冷键请求各 10 轮，均只触发一次回源。

可引用的验证：MySQL 8.4.8 上 Flyway V1–V7 新库迁移通过，16 张应用业务表为 0 自增列、0 物理外键；隔离真实 Redis/RocketMQ 的 15+3 项测试通过。2026-09-29 完整 Compose 复验课程页面和 API、两级缓存命中、失败冷却与会话淘汰；fixture 跨服务烟测确认直接抢课和 Agent 审批均形成零元订单并保持库存守恒。课程新增 14 项测试包括 7 项 Redis/跨 JVM、4 项 MySQL 查询、3 项鉴权。

2026-10-01 新增可引用结果如下，完整条件、原始数据入口与排除记录见[实验报告](../../experiments/reports/2026-10-01-实验报告.md)：

| 场景 | 已测条件 | 可引用结果 |
|---|---|---|
| 课程缓存 | 同一 JAR、鉴权和资源配额，默认首页/固定详情各半；400 RPS，每档 3×180 秒 | MySQL/Redis/两级缓存 HTTP P95 三轮中位数为 3.935/2.786/2.446 ms；两级相对直查的目录 SQL 减少 99.9917%，相对 Redis 的目录首次共享缓存查找减少 99.95% |
| 试听异步成单 | 80 个新增申请/s＋20% HTTP 重放，补发批量均为 30，仅将补发间隔从 1,000 ms 改为 100 ms | 窗口订单 TPS 三轮中位数由 25.50 增至 79.95（3.14 倍），请求到订单时间戳差 P95 由 63.117 s 降至 230 ms；两组 30 个阶段共生成 26,700 笔订单，未观察到超卖或重复订单 |
| Agent 恢复与幂等 | fixture、单 worker、真实 Java/数据库；四类场景各 20 例 | 正式 80/80 通过，含 60 次进程故障与 20 组共 500 次附加重放；零重复动作、零未批准副作用 |
| 真实模型任务 | qwen3.7-flash，顺序执行 5 条开发样本与 30 条保留样本 | 开发样本 4/5 通过，保留样本 21/30 通过（规则通过率 70%）；35 条任务均保存 MySQL 快照，实际 1 笔预约、3 笔试听订单与 Java 回执一致 |

缓存 P95 是各轮 P95 的中位数；400 RPS 为固定测试到达率，三档成功吞吐均约 400 请求/s，不作为最大 QPS 或缓存吞吐提升的证据。秒杀窗口 TPS 统计首个数据库申请后 `[5,25)` 秒内的订单数 / 20 秒；成单时延采用申请与订单数据库时间戳差，不能当作 HTTP 受理耗时。真实模型的 70% 是冻结评分器的规则通过率，自然语言语义正确性未评分；RAG 保留集三种检索的 Recall@5 均为 100%，未观察到融合质量增益。

仍未验收真实 API 的 MEMBER 浏览器权限、浏览器内 Agent 审批与会话淘汰后任务续跑；生产最大 QPS、真实用户规模及线上收益也未测量。简历可引用上述实测数据并注明条件，其他数值需有对应实验支持。

## 面试追问与证据

| 问题 | 关键回答 | 证据 |
|---|---|---|
| 为什么 Agent 不直接执行抢课？ | 模型只能查询和起草；用户批准固定活动参数，Java 再按可信 actor/workspace/run 执行 | [产品契约](../product/产品功能说明书-研发版.md)、[模块设计](../modules/免费试听秒杀与Agent联动.md) |
| 事务消息为何还需要幂等？ | 半消息与本地事务缩小不确定窗口，消费者仍可能重复；请求、库存条件更新和订单唯一键决定最终结果 | [模块设计](../modules/免费试听秒杀与Agent联动.md)、[验证记录](../modules/免费试听秒杀验证记录.md) |
| 为什么预占成功不等于抢到？ | Redis 只是准入层；消费者 MySQL 事务提交并返回 `SUCCEEDED + orderId` 才是订单事实 | [接口契约](研发接口契约.md)、[模块状态](../modules/免费试听秒杀与Agent联动.md) |
| Redis 丢失活动库存怎么办？ | 停止受理，保留持久请求与订单，对账和人工裁决；不能按数据库剩余量覆盖预占键 | [恢复边界](../modules/免费试听秒杀与Agent联动.md) |
| checkpoint 已保存为何仍需 actionId？ | Java 业务已提交而图尚未保存下一节点时会重放，原 actionId 查回同一业务结果 | [接口契约](研发接口契约.md) |
| 为什么取消物理外键后仍要校验关联？ | 服务端写入前核对空间、用户、课程、校区等关联；数据库仍保留唯一键、非空和库存条件更新，避免把“无物理 FK”理解为无约束 | [Java 业务实现](Java业务改造与验证记录.md) |
| 雪花 ID 的验收边界是什么？ | 业务主键由应用生成，节点编号避免冲突；验证结构中无自增列，并在实际业务写入中检查 ID、引用与幂等键 | [部署与结构验证](开发与验证记录.md) |
| 登录限流为何放在 BCrypt 前，还要并发上限？ | BCrypt 刻意消耗 CPU；频率限制控制窗口内尝试数，`Semaphore.tryAcquire` 控制本机同时执行数并立即拒绝。账号额度用数据库 ID，避免用户名大小写变体绕过 | [登录保护](../modules/登录保护.md) |
| 会话淘汰与续期同时发生怎么办？ | Lua 原子检查 Token 与账号索引，淘汰删除旧 Token；续期不创建缺失会话，也不改变创建排名。后台 Agent 使用内部凭据与持久化任务身份，不随浏览器 Token 淘汰而取消 | [会话实现与测试](../modules/登录保护.md) |
| Caffeine 和 Redisson 分别解决什么？ | Caffeine 减少同实例重复读取并合并同键加载；Redis 共享展示缓存；Redisson 在 Redis 未命中时协调跨实例回源，拿锁后再次检查缓存 | [课程缓存流程与测试](../modules/课程目录与两级缓存.md) |
| 为什么课程缓存不用于库存、审批或登录？ | 课程是低频变化的展示数据，可以接受 TTL 延迟；库存和身份各自依赖原子业务规则，继续由现有 Lua、事务与鉴权处理 | [课程缓存范围](../modules/课程目录与两级缓存.md) |
| 缓存有什么一致性与性能证据？ | 默认本地 10 秒、Redis 60 秒，展示允许约 70 秒加查询耗时的延迟；本机 400 RPS 下 HTTP P95 三轮中位数由 3.935 ms 降至 2.446 ms，目录 SQL 减少 99.9917%；双实例冷键 20 轮每轮只回源一次。已测固定热读负载，生产最大容量未测 | [课程验证](../modules/课程目录与两级缓存.md)、[2026-10-01 实验报告](../../experiments/reports/2026-10-01-实验报告.md)、[证据汇总](../../experiments/evidence/2026-10-01-summary.json) |

面试展示每个数字时，连同测试环境、模型类型和日期一起说明。现有证据包括完整 Compose 的 fixture 联调、真实课程页面、登录保护 API、隔离中间件测试，以及 2026-10-01 的缓存与成单对照、故障恢复、真实模型任务和 RAG 评测；生产容量仍需扩展数据规模、有效负载发生器与冷热场景，结合错误率、尾时延和资源饱和确定容量拐点。
