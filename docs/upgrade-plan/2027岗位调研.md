## 证据规则与核心结论

A1 = 官方完整 JD，并由岗位详情或同站官方批次页明确 2027 届正式/应届/秋招；A2 = 官方完整 JD，但为实习或社招，单独注明；B = 官方项目/列表，仅能证明批次、岗位名或可见职责片段；C = 第三方转载/聚合，仅作为找原文线索，不替代官方要求。招聘页面可随时更新，某些名称与旧博客引用已不同。

这里有 8 个 A1 完整 JD 样本（含 1 个算法研究边界样本）以及 5 个 A2 工程/实习参照。样本用于设计项目能力覆盖，不是招聘市场统计，不做“多数公司必用某框架”的推断。

最强的项目定位是“Java 业务后端 + Python Agent Runtime + 可回放评测与可观测平台”。这是基于岗位共性做出的研发建议，而不是企业公开了相同内部架构。Java 并没有因 AI 过时：字节 2027 后端岗位、阿里 2027 AI 应用及 Agent Infra 岗均允许 Java；Python 应用于 Agent 运行时、评测、训练工具更有直接岗位支撑。应把 Agent 的任务执行、可靠性和效果量化做深，同时保留数据库、并发、消息、缓存、网络与系统基础。

## 对研发方案的具体映射（研究建议）

| 能力 | Agent 研发主线 | 通用后端主线 | 该项目应交付的证据 |
|---|---|---|---|
| 编程与系统 | Python asyncio、类型/数据校验、流式协议 | Java 并发、JVM、数据库、网络 | 核心代码、基准、排障记录 |
| Agent 运行时 | Plan/Act/Observe、工具结果驱动下一步、持久化状态、受限反思 | 持久任务、状态机、幂等和重试 | 任务执行状态图、断点恢复演示 |
| RAG/上下文 | 混合检索、重排、证据引用、上下文预算 | 索引、数据一致性、异步入库 | 可复现检索集、Recall@k/nDCG、归因 |
| 工具与协议 | MCP/SDK、结构化输入输出、权限注入、受限执行 | API 契约、鉴权、租户隔离、限流 | 工具契约、拒绝越权、审计轨迹 |
| 效果迭代 | 任务成功率、工具正确率、失败分类、回放与评测 | 回归测试、服务 SLO、压测和故障注入 | 固定数据集、基线/消融、版本对比 |
| 可靠性 | 模型失败/429/超时恢复、预算与循环限制 | MQ、事务、Outbox、缓存和熔断 | 中途崩溃恢复、重复事件无副作用 |
| 观测与成本 | Trace 到模型/检索/工具，token 与调用成本 | 指标/日志/trace、p95/p99 | 一条 trace 定位失败、成本报表 |
| 模型算法 | Transformer、SFT/LoRA/DPO 基本原理，必要时小实验 | 与推理服务解耦，模型接口治理 | 可选小规模微调对照；不虚构训练规模 |

建议安排 Agent 能力约 60%、后端基础设施约 40% 的展示重点。这是对用户“双线准备，Agent 多一些”的方案分配，不是 JD 统计。核心项目必须能独立跑完真实业务任务；“模型选型、记忆策略、是否多 Agent”的决定都通过数据验证。接口调用成功率与业务任务完成率分开统计；无 GPU 时先用托管模型完成工程实验，不为岗位词条机械加入训练集群。框架只选一条主运行时，做到理解执行与恢复语义，再用小实验比较另一条，不把 LangGraph、AutoGen、CrewAI、ADK 全部堆进一个主链路。

以上样本没有证明某家公司“统一用 Java + LangGraph + 某向量库”。报告应写“岗位要求/官方公开产品或框架方向支持这种能力”，不要写“某大厂全公司都在用这套栈”。
